问问大师 wenV6（正式版）是一个探索东方命理与西方星象的 Web 应用。输入出生信息后，可以查看八字、紫微斗数和西方星盘等报告，也可以使用决策工具、角色向导和 AI 问答。

**[在线体验](https://kynessiscozy.github.io/wenV5/funnel.html)** · [更新日志](./CHANGELOG.md) · [贡献指南](./CONTRIBUTING.md) · [统一文案源](./src/product-copy.js)

> **版本说明**：当前产品正式版本号为 **wenV6**。源码仓库名 `wenV5`、历史验证报告标题与历史 release 链接均为历史沿用，不代表当前版本；全站文案与版本号以 [`src/product-copy.js`](./src/product-copy.js) 为准，改文案后执行 `npm run sync:copy` 同步、`npm run check:copy` 校验。
>
> 推演结果仅供文化研究与娱乐参考，不构成医疗、投资或其他重大决策建议；完整免责声明见下文「免责声明」一章。

## 功能概览

- **东方命理**：四柱八字、五行十神、紫微斗数、梅花易数、流日与双人合盘；支持节气和真太阳时校正。
- **西方星象**：本命星盘、行星落座与宫位、相位、生命灵数，以及可交互的 Three.js 星象场景。
- **工具中心**：塔罗、MBTI、择日、合盘、起名、答案之书、日签等工具。
- **角色与分享**：选择引路人，获得不同的阅读线索与反思问题；引路人不改变排盘或评分。可在本机预览、生成分享海报。
- **AI 问答**：默认走内置模型（免密钥），结合命盘上下文流式追问；可在「AI 设置」切换 DeepSeek / OpenRouter 并自填 API Key，连接失败时回退本地知识库与离线回答。
- **PWA**：支持安装到主屏幕；资源缓存完成后，部分入口和推演功能可离线使用。

## 使用指南

> 以下「使用指南 / 关于问问大师 / 免责声明」三节与应用内弹窗同源，均由 `src/product-copy.js` 统一生成；改文案请先改数据源，再执行 `npm run sync:copy`。应用内可在菜单底部打开同样内容。

### 开始 · 一起看看，慢慢探索

选择一位引路人，再从自己的问题出发。

1. **选择引路人**：首次进入在漏斗首屏挑选同行形象，它只决定角色与演出，不参与命盘计算；进入应用后仍可更换。
2. **填写出生信息**：填写日期、时间和地点后开始推演。结果出现后会停留，点击「查看报告」继续。
3. **阅读报告**：先看同行卡中的命盘信息；用顶部切换东方与西方，底部切换命盘、运势和关系。卡片里的按钮可继续查看细节。
4. **继续探索**：工具页有不同主题的体验。问问对话默认使用内置模型，无需填写 API Key；也可在「AI 设置」里切换服务商。

### 东方 · 先看一览，再看依据

四柱和五行是一套传统的解读方式，不是对人生的定论。

1. **日主与四柱**：四柱由出生的年、月、日、时组成。日柱的天干称为日主，是阅读其余干支关系的起点。
2. **五行与用神**：一览显示日主、强弱、用神和格局。打开「五行结构」可查看分布；不同方法的判断可能不同。
3. **时间与关系**：在运势页查看大运、流年等时间线，在关系页阅读相处角度；结合现实处境判断，不必照单全收。

### 西方 · 从太阳、月亮和上升开始

出生时间和地点会影响结果。星盘按出生地时区及历史夏令时计算；夏令时切换时的重复或不存在的时间可能产生偏差。

1. **认识三个起点**：太阳、月亮和上升分别是占星解读中常用的三个视角。继续阅读可查看行星、宫位和相位。
2. **与星盘互动**：拖动场景可旋转视角，点击人物可收起立绘，再用「显示立绘」恢复。鼠标滚轮可缩放，复位按钮可返回初始视角。设备不支持 3D 时仍可阅读文字报告。
3. **查看星座参考**：星座运势文字和分值按日期与星座生成，不是实时天象或现实事件预测；六维图也是星座模板，并非科学测量。
4. **探索灵数**：关系页也提供基于出生日期的生命灵数体验。它是另一种解读框架，并非科学测量。

### 术语 · 遇到生词，先看这里

这些解释帮助你理解报告里的基本概念。

| 术语 | 体系 | 解释 |
| --- | --- | --- |
| 四柱 | 东方 | 出生年、月、日、时对应的四组干支。 |
| 日主 | 东方 | 日柱的天干，是四柱解读的参照。 |
| 用神 | 东方 | 传统命理中用于分析命局平衡的要素。 |
| 大运 / 流年 | 东方 | 分别指较长阶段与单年的时间线索。 |
| 上升 | 西方 | 出生时东方地平线升起的星座，受时间和地点影响。 |
| 相位 | 西方 | 星盘中天体之间的特定角度关系。 |

### 问答 · 使用前，了解这些

信息越准确，越方便你理解这份报告的计算前提。

- **不记得出生时间怎么办？** 请尽量核实。表单默认时间是 09:00；如果不确定，结果只是按所填时间计算，时柱和上升等内容可能不同。
- **引路人会影响命盘吗？** 不会。引路人只决定同行形象与演出，不参与命盘计算；可以随时更换，也可以取消。
- **信息会保存或发送吗？** 档案和部分偏好保存在本机浏览器。问问对话默认使用内置模型，问题和相关上下文会发送给所选服务商；若自行配置第三方 API Key，密钥也会发送给该服务商。请避免输入敏感信息并留意其隐私政策。
- **天气和定位如何使用？** 打开菜单、穿搭或风水工具会尝试定位并联网查询。未授权时天气会尝试使用北京默认值；风水周边查询也会向外部服务发送坐标。
- **结果可以用来做决定吗？** 报告和 AI 回答可能不准确，仅供文化体验与自我反思。医疗、法律、财务等重要决定请结合现实情况并咨询专业人士。

## 本地开发

### 环境要求

- Node.js 24 或更高版本，以及 npm
- 运行浏览器测试时需要 Puppeteer 可用的 Chrome 和相应系统依赖

### 安装与启动

```bash
git clone https://github.com/kynessiscozy/wenV5.git
cd wenV5
npm ci
npm run dev
```

打开 <http://localhost:5173/funnel.html>。开发服务器默认监听 5173 端口，也可通过 `PORT` 环境变量指定端口。

### 构建与预览

```bash
npm run build      # 输出到 dist/
npm run preview    # 预览生产构建，默认端口 4173
npm run size       # 构建并统计产物大小
```

预览时访问 <http://localhost:4173/funnel.html>。应用使用相对基础路径，可以部署在静态站点的子路径下；PWA 和 Service Worker 需要 HTTPS 或 localhost 等安全上下文。

## 实现与限制

项目使用原生 ES Modules 和 Vite 构建；Three.js 场景和部分工具按需加载。命理计算主要在浏览器中进行，Puppeteer 用于浏览器回归测试。

| 模块 | 实现与范围 |
| --- | --- |
| 八字与历法 | `src/engines/bazi.js`、`calendar.js`、`solar-terms.js`；支持节气和真太阳时校正 |
| 农历 | `src/engines/lunar.js`；数据表覆盖 1900–2100 年，含闰月 |
| 紫微斗数 | `src/engines/ziwei.js`；标准安星，尚不包含部分杂曜、飞星四化及大限等内容 |
| 奇门遁甲 | `src/engines/qimen.js`；当前为简化排盘，用于九宫速览，不是完整时家转盘 |
| 西方星象 | `src/engines/western.js`；包含星历、宫位、相位与生命灵数计算，部分天体计算使用近似模型 |

历史交叉验证结果及计算范围见 [算法验证报告](./docs/algo-verification-2026-10-13.md)和[数据审计报告](./docs/audit-deep-2026-10-13.md)。这些验证不能保证所有日期、流派或使用场景下的结果完全一致。

### 入口流程

`public/funnel.html` 是问卷入口；主应用由 `src/ui/entry-plan.js` 决定初始路径，由 `src/ui/entry-flow.js` 管理界面状态。直接访问、深链、档案载入和问卷交接使用同一套流程。旧首页和特质轮盘的 DOM 保留供报告等功能复用，但不再作为可交互入口。

## 隐私与外部服务

- 出生信息、档案、API Key 和自进化偏好默认保存在浏览器本地；清除浏览器数据可能导致其丢失。档案可通过应用导出、导入，请妥善保管导出文件。
- 使用外部 AI 时，API Key、问题、近期对话及相关命盘或工具上下文可能发送给所选服务商；连接检测也会发送 Key。请勿输入不愿与服务商分享的敏感信息，并留意其隐私政策和费用。
- 天气功能使用定位及外部天气、地理编码服务；使用相关功能时，位置信息可能发送给这些服务。
- 离线能力依赖浏览器和已缓存资源；外部 AI、天气等联网功能在离线时不可用。

## 部署与贡献

推送到 `main` 或手动触发 GitHub Actions 后，[部署工作流](./.github/workflows/deploy.yml)会先构建并运行单元测试，再将 `dist/` 发布到 GitHub Pages。其他静态托管环境也可发布该目录。

欢迎提交问题和改进建议。开发规范、提交前检查及 PR 指南请参阅 [CONTRIBUTING.md](./CONTRIBUTING.md)；版本历史见 [CHANGELOG.md](./CHANGELOG.md)。
